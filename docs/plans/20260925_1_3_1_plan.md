## Findings behind the design (probes 2026-09-25, IGV 2.19.8)
- `goto` always returns `OK` (`CommandExecutor.goto1` calls the void `IGV.goToLocus`), so a failed search is
  never logged. After a successful region, a failed `goto` (unknown gene, unknown contig, start beyond the
  chromosome end) **keeps the previous region on screen**: the snapshot shows the wrong region under the new
  name. Only a failure on the first region shows the whole genome.
- A bare `snapshot` (no filename) is named after IGV's current locus (`FrameManager.getCurrentLocusString`,
  `:`/`-` → `_`): `chr8_32,534,767_32,536,767.png`, split view `a | b.png`, whole genome `All_1_3,095,677.png`.
  It is always a PNG, also when the real snapshot is SVG, and has the real snapshot's canvas size.
- `gotoimmediate All` after each region resets the view, so every failure lands on `All`. A split view with one
  bad locus silently drops it (fewer ` | ` frames).
- Cost of reset + verification snapshot: 26.4/26.9 s → 28.5/28.9 s for 20 regions (~0.1 s per region).
- IGV 2.19.8 SVGs have no width/height/viewBox. Injecting the verification PNG's size makes cairosvg write a
  correct PDF (100 KB; pdftoppm render matches the PNG layout). The image also needs `python-cairosvg`.

## U1 — unknown gene / contig / out-of-range locus (S1)
Design. Each region block becomes
`goto X` · display/maxPanelHeight/prefs · `snapshotDirectory <verify>/<i>` · `snapshot` · `snapshotDirectory <out>` ·
`snapshot <name>` · `gotoimmediate All`. `<verify>` = `igver_verify_*` under `$TMPDIR` (else the output dir),
subdirs created when the batch is written. `_snapshot_name` reads the last `snapshot ` line. After the retry loop,
`run_igv` reads each rendered block's verification PNG: first frame `All` (exact) for a request other than `All`
→ not found; fewer frames than requested loci → a locus was dropped. The wrong snapshots are deleted, the good
ones kept, and igver exits 1 listing every failed region. A missing verification PNG only warns. The verify dir
is deleted on success, kept on failure. The 1.3.0 "whole-genome" warning for gene names is removed.
Done when.
- [ ] Unit: block shape; `_snapshot_name` with the trailing reset; not-found / dropped-locus / `All` requested /
      missing verify PNG / correct locus, via a fake IGV that writes verification PNGs; wrong snapshot deleted.
- [ ] E2E (both modes): U1a good region then unknown contig → exit 1, good PNG kept (opened), bad absent,
      message names the region; U1b split view with a bad locus → exit 1; U1c start beyond chromosome end →
      exit 1; U1d `-r TP53` renders the gene (opened); U1e `-r All` renders; E5b now exits 1 (intended change).
- [ ] No `igver_*` left in TMPDIR after a successful run.

## U2 — `-f pdf` (pre-existing since 1.2.x)
Design. Before conversion (and for `-f svg` too), write `width`/`height`/`viewBox` from the region's verification
PNG into the SVG root when it has none; then cairosvg. Dockerfile installs `python-cairosvg`.
Done when.
- [ ] Unit: an unsized SVG gets the PNG's size; an already-sized SVG is untouched; PDF conversion of the fixture
      produces a non-empty PDF.
- [ ] E2E R4 (both modes and the release gate): PDF + SVG written, exit 0, PDF > 20 KB and rasterises (pdftoppm)
      to 1150 px wide (opened).

## Design changes
(append here: date, item, what changed, why)
- 2026-09-25 · U1 · Verification PNGs are deleted once read, also for failed regions: the error message carries
  what IGV showed (`IGV showed only 1 of 2 loci ('chr8_…')`, "showed the whole genome"), so nothing is kept in
  TMPDIR after a verification failure. Verification subdirs of regions IGV never rendered are kept, because the
  kept batch for those regions still references them.
- 2026-09-25 · U2 · The PDF page is the canvas at `--dpi` (cairosvg `dpi=`, default 300, unchanged since 1.2.0):
  1150 px → 3.83 in. The first test drafts assumed 96 dpi; the unit test now checks both `--dpi 300` (default)
  and `--dpi 96`, and the e2e `pdf_width` check rasterises at 300 dpi.
- 2026-09-25 · U1 · `test_batch_chunking.py::test_split_batch_roundtrip` asserted that a block ends with its
  `snapshot` line; blocks now end with `snapshot <name>` + `gotoimmediate All`, and the assertion checks exactly that.
